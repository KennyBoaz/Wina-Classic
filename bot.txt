Absolutely. I would design V1 as a **proper customer-conversation platform with an AI receptionist**, rather than a WhatsApp bot with a few hard-coded replies.

The core principle is:

> **AI understands and qualifies the customer; deterministic backend logic controls business actions, routing, permissions, and staff assignment.**

That separation will make the system much easier to trust, debug, and expand.

For the AI layer, the current Vercel AI SDK is a good fit because it supports structured output, tool calling, agents, multi-step tools, and multiple model providers; AI Gateway can also provide a single model-access layer. ([AI SDK][1])

# 2. Technology stack

I'd use this for V1:

| Layer              | Technology                                |
| ------------------ | ----------------------------------------- |
| Frontend           | Next.js + React                           |
| Backend            | Next.js Route Handlers / TypeScript       |
| AI                 | Vercel AI SDK                             |
| Model access       | Vercel AI Gateway                         |
| Primary model      | A strong general-purpose model            |
| Database           | PostgreSQL                                |
| ORM                | Drizzle ORM                               |
| WhatsApp           | Meta WhatsApp Cloud API                   |
| Authentication     | Auth.js or Clerk                          |
| Hosting            | Vercel                                    |
| Realtime dashboard | WebSockets/SSE or polling initially       |
| Validation         | Zod                                       |
| Logging            | structured application logs               |
| Background jobs    | Vercel Workflow/queue mechanism as needed |

The AI SDK currently supports tool calling and structured output, while Vercel's AI Gateway provides access to multiple providers through a common interface. ([AI SDK][1])

This means you aren't locking the whole system to one AI provider.

Don't let the AI return only:

```text

```

```json
{
  "intent": "PURCHASE",
  "intentConfidence": 0.96,
  "stage": "QUALIFYING",

  "customerNeeds": {
    "product": "Product X",
    "quantity": 20,

  ],

  "qualification": {

    "score": 72
  },

  "recommendedAction": "ASK_QUESTION"

```

The application then decides what to do.

This is exactly where structured output/tool calling is useful in the AI SDK. ([AI SDK][1])

# 23. The WhatsApp message flow

Let's walk through a real example.

Customer:

> "Hello, I need 20 boxes of Product X."

### Step 1

WhatsApp sends webhook.

```text
POST /api/webhooks/whatsapp
```

### Step 2

Your server identifies:

```text
WhatsApp number = +256...
```

### Step 3

Find customer.

If not found:

```text
CREATE CUSTOMER
```

### Step 4

Find active conversation.

If none:

```text
CREATE CONVERSATION
```

### Step 5

Store incoming message.

```text
messages
sender_type = CUSTOMER
```

### Step 6

Conversation processor starts.

```text
stage = DISCOVERY
```

### Step 7

AI determines:

```text
intent = PURCHASE
product = Product X
quantity = 20
```

### Step 8

AI calls:

```text
searchProducts("Product X")
```

### Step 9

Backend responds:

```text
Product X
Available: 35
Price: ...
```

### Step 10

AI asks:

> "Yes, we have Product X available. What location should we deliver to?"

Customer:

> "Ntinda."

### Step 11

Qualification engine updates:

```json
{
  "product": "Product X",
  "quantity": 20,
  "location": "Ntinda"
}
```

### Step 12

Customer confirms purchase interest.

Now:

```text
qualification.status = QUALIFIED
```

### Step 13

Create lead.

```text
lead.status = QUALIFIED
```

### Step 14

Routing engine runs.

# 24. Staff-routing algorithm

Here's how I'd implement it.

## Step 1 — Determine required department

From intent:

```text
PURCHASE → Sales
BULK_ORDER → Sales
PAYMENT → Accounts
DELIVERY → Delivery
COMPLAINT → Customer Support
TECHNICAL → Technical Support
```

This should be configured in your database, not hard-coded forever.

---

# 25. Step 2 — Determine required skills

Example:

```text
BULK_ORDER

required skills:
    Bulk Sales
    Product Sales
```

Then query staff.

```text
WHERE
department = Sales
AND active = true
AND availability != OFFLINE
```

---

# 26. Step 3 — Remove ineligible staff

Exclude:

```text
OFFLINE
```

Exclude:

```text
current_active_conversations >= max_active_conversations
```

Exclude people who don't possess required skills.

Exclude staff who are unavailable for the relevant business hours.

---

# 27. Step 4 — Calculate routing score

I'd use:

```text
ROUTING SCORE

Skill match              40 points
Department match         25 points
Availability              15 points
Current workload          10 points
Priority/specialization    5 points
Previous customer link     5 points
                         ──────────
                           100
```

Example:

### Sarah

```text
Skill match:       40
Department:        25
Availability:      15
Workload:            8
Specialization:      5
Previous customer:   0
                     ---
                     93
```

# 28. But don't let workload scoring become unfair

There's an important adjustment.

You don't want:

```text
Sarah keeps getting customers
because she's good.
```

while everyone else gets nothing.

So I'd implement a workload penalty:

```text
workloadPenalty =
    currentActive / maxActive
```

Then normalize the score.

This encourages the system to distribute work.

# 29. Routing pseudocode

```typescript
async function routeConversation(conversationId: string) {

  const conversation =
    await getConversation(conversationId);

  const requirements =
    await determineRoutingRequirements(conversation);

  const candidates =
    await getEligibleStaff({
      department: requirements.department,
      skills: requirements.skills
    });

  if (candidates.length === 0) {
    return await escalateToFallback(conversation);
  }

  const scored = candidates.map(staff => {

    const skillScore =
      calculateSkillMatch(staff, requirements.skills);

    const departmentScore =
      staff.departmentId === requirements.departmentId
        ? 25
        : 0;

    const availabilityScore =
      calculateAvailability(staff);

    const workloadScore =
      calculateWorkloadScore(staff);

    const specializationScore =
      calculateSpecialization(staff, requirements);

    const previousRelationshipScore =
      calculateCustomerRelationship(
        staff,
        conversation.customerId
      );

    const total =
      skillScore +
      departmentScore +
      availabilityScore +
      workloadScore +
      specializationScore +
      previousRelationshipScore;

    return {
      staff,
      score: total
    };
  });

  scored.sort((a, b) => b.score - a.score);

  const selected = scored[0];

  return assignStaff(
    conversationId,
    selected.staff.id,
    selected.score
  );
}
```
